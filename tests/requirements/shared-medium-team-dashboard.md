# Team Dashboard Delivery Requirement

Build a small but complete internal team dashboard for tracking project check-ins.

## Goal

Deliver a runnable web app that lets a small team:

- view a dashboard of project check-ins
- add a new check-in with project name, owner, status, and summary
- filter the list by status
- show a compact stats area with counts per status

## Technical expectations

- use a lightweight backend service with documented start instructions
- provide a simple web UI that can be previewed from TeamClaw
- keep implementation scope moderate: no authentication, no database server, no external APIs
- local file storage or in-memory storage with a seeded sample dataset is acceptable
- include clear README/setup notes

## Quality expectations

- architecture should be intentionally simple and explained briefly
- implementation should be clean and runnable
- QA should verify the happy path plus a few validation/error cases
- if tests are practical, include a minimal automated test or validation script

## Deliverables

- source code for the backend and frontend
- a short README describing how to run and verify the app
- any test notes or validation output needed for QA handoff
